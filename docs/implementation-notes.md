## 0. プロジェクト概要

| 項目 | 内容 |
|---|---|
| 目的 | 2026年11月の韓国学会 ISSY39(招待講演+シンポジウム)と、2027年1月の結婚式(香港人パートナーのご両親と広東語)に向けた、会話力・発表力のトレーニング |
| 形式 | PWA(純粋なHTML/CSS/JavaScript、ビルド不要)。AndroidのChromeでホーム画面に追加して使用 |
| 公開 | GitHub Pages (`rafysta/confquest`) |
| 特徴 | 学習機能 + ローグライクゲーム + 継続の仕組み(Duolingo型) |

## 1. 発表練習モード

学会・シンポジウムでの自分の発表を練習する。`js/practice.js` + app.js の該当部分。

**画面**: `setup`(設定) → `practice`(練習中) → `results`(結果) → `qa`(Q&Aシミュレータ)

### 機能

| 機能 | 詳細 |
|---|---|
| PDFスライド | PDF.js でレンダリング。連打時は前の描画を`cancel()`してエラーを防止 |
| スライド送り | 画面の右70%タップで次、左30%で前。タップ時に青くフラッシュ |
| 時間管理 | 全体タイマー、スライド毎の滞在時間、**終了予測時刻**をリアルタイム算出 |
| ペース警告 | 予測が目標を30秒超過で「⚠ このペースだと N 超過します」、30秒早いと逆の警告 |
| 録音 | MediaRecorder。終了後に`<audio>`で再生可能 |
| 文字起こし | 録音終了後に Whisper API で一括処理。`verbose_json`のsegmentsを**タイムラインと突き合わせてスライド毎に割り当て** |
| 統計 | WPM(話速)、filler語の検出(設定でリスト編集可) |
| AIフィードバック | 良かった点2つ / 直すべき3点 / 英語表現の改善。Markdown整形で表示 |
| Q&Aシミュレータ | 4つのpersona(学生/分野外/専門家/厳しい査読者)と英語で質疑応答 |
| 履歴 | 時間・WPM・filler・スコアを保存(`lq_history`) |

### スコア算出

100点から減点方式。目標時間との乖離(1分あたり-8、最大-35)、WPMが110未満/170超で最大-15、filler語が毎分3回超で最大-20。下限10点。

### 重要な設計判断

**リアルタイム音声認識(SpeechRecognition)は使わない**。Androidでは録音とマイクを取り合って共存できず、認識の自動再起動のたびに通知音が鳴るため。録音終了後の一括文字起こしに変更した(v0.1.1)。

※これは音声「認識」の話。音声「合成」(`speechSynthesis`)は問題なく使えるので、今後の言語学習モジュールでは利用可能。

## 2. 講演録音・要約モード

学会で**聴いた**発表を記録し、PCで整理できる形にする。`js/talk.js`。

**画面**: `talk-setup` → `talk-record`(録音中) → `talk-result`(要約) / `talk-list`(保存一覧)

### 機能

| 機能 | 詳細 |
|---|---|
| 録音 | 32kbps mono(30分で約7MB。Whisperの25MB上限に余裕) |
| ⭐ここは重要 | 録音中に押すと時刻を記録。**前後25秒の発話**を抽出し、要約プロンプトで重点扱いを指示 |
| メモ | 自分の研究との関連などを記入。要約に反映される |
| 要約 | 概要 / 背景と問い / 手法 / 主要な結果 / 結論 / **質問候補(英語)** / キーワード |
| 共有 | Web Share API。Nextcloudアプリを選べばPCの同期フォルダに`.md`が届く。ファイル保存・コピーも可 |
| 保存 | 音声は保存せずテキストのみ50件まで(`lq_talks`) |

### 注意

- 25MB超はエラーで停止(講演ごとに分けて録音するよう案内)
- 共有はファイル共有を優先し、非対応環境ではテキスト共有にフォールバック

## 3. 会話トレーニングモード(選択肢バトル)

懇親会での立ち回りを、制限時間つきの4択で鍛える。`js/scenarios.js` + `js/convo.js`。

**画面**: `convo-list`(場面選択) → `convo-play`

### 収録内容(4場面 × 4ターン = 16ターン、64選択肢)

1. 初対面の研究者に話しかける(Lv1)
2. 会話が途切れたときの立て直し(Lv2)
3. 自分の研究をいつ、どう出すか(Lv2)
4. 研究以外の雑談を広げる(Lv3)

### ルール

- 好感度50から開始。選択の`delta`(-3〜+3)× 6 で増減、0〜100でクリップ
- 制限時間10〜14秒 × **設定の倍率**(じっくり2.0 / ゆっくり1.5(初期値) / 標準1.0 / ハード0.75)
- `delta >= 2` の選択を残り時間半分以上で選ぶと**即答ボーナス** +1
- 時間切れは -2
- 選択肢は毎回シャッフル(位置で覚えられない)
- 最終好感度でS〜Dのランク判定(90/75/60/45が境界)
- 全選択肢に日本語の解説。外した場面は終了後に「見直しポイント」として表示
- 解説画面と見直しに**状況文を再表示**(時間内に読み切れなかった英文を振り返れる)

### 能力値(Stats)

`Networking / English / Confidence / Topics` の4つ。XPで成長し、レベルは緩やかな曲線(Lv2に50XP、以降必要量が1.25倍ずつ増加)。シナリオの`focus`に応じて配分される。**ラン失敗でも失われない恒久的な成長**。

獲得XPの目安:

| 行動 | XP |
|---|---|
| 会話トレーニング1回 | 好感度/4 + ベスト選択数×5 |
| ランの通常戦闘 | 5 + ベスト数×5 |
| ランのエリート戦 | +15 |
| ランのボス戦 | +25 |
| 休憩所で「予習する」 | 好きな能力に +30 |

### データ構造(scenarios.js)

```js
{
  id, title, icon, level,
  setting,                    // 場面の説明
  partner: { name, desc },
  focus: ['network', ...],    // XPの配分先
  turns: [{
    situation,                // Markdown可
    limitSec,                 // 基準時間(設定倍率が掛かる)
    choices: [{ text, delta, why, best }]  // 4つ。bestは1つだけ
  }]
}
```

新しい場面を追加するときは、この形式で`SCENARIOS`に足すだけで一覧画面に自動で出る。

## 4. 学会攻略モード(ローグライク)

Slay the Spire型。会話が戦闘。`js/run.js` + `cards.js` + `minigames.js` + `bosses.js`。設計の全体像は `docs/game-design.md`。

**画面**: `run-map` → `run-battle` / `run-event` → `run-result`

### 構造

- **1ラン = 学会3日間**: Day 1 レセプション → Day 2 本会議 → Day 3 シンポジウム
- 各日 = 8層の分岐マップ。最上段がボス
- 日が変わるとマップ再生成、🧠+15回復、研究費とアイテムは持ち越し

### リソース

| リソース | 初期値 | 説明 |
|---|---|---|
| 🧠 メンタル(HP) | 50 | 悪い選択でダメージ。0でゲームオーバー |
| 💰 研究費 | 30 | お店で使う。クリア時に⭐へ換金 |
| 🎒 アイテム | 0 | HUDの2行目に折り返し表示。タップで説明/ドリンクは使用 |

### ノード種別

| 記号 | 種別 | 内容 |
|---|---|---|
| 💬 | 研究者 | 通常戦闘。RUN_CARDS(20枚)から抽選。1ターン |
| 🎁 | お宝 | スロット(30%) / 豆知識クイズ(25%) / 語学クイズ(25%) / 無条件報酬(20%) |
| 🛒 | お店 | ガジェット3種+レリック(60%で1種)+ドリンク3種。売値は買値の60% |
| ☕ | 休憩所 | 🧠30%回復 か 好きな能力に+30XP の二択 |
| ❓ | ランダム | ルーレット演出 → エレベーター/コーヒーこぼし/落とし物/抽選会/旧友 |
| ⭐ | エリート | 中盤に最大1つ。既存4ターンシナリオ。報酬2.5倍+🏆 |
| 👑 | ボス | 最上段。ダメージ1.5倍。演出後に開始 |

**マップ生成の保証**: 8層、最下段3ノード、中間層は2〜4ノード、最上段はボス1つ。お店と休憩所は必ず1つ以上出現(`forceType`が互いを上書きしないよう制御)。エリートは最大1つ。全ノードに入出力の辺が最低1本ずつ張られる(行き止まりが生じない)。

出現率(中間層): 研究者42% / お宝15% / ランダム13% / 休憩所12% / お店11% / エリート7%

### ダメージと報酬

```
ダメージ = |delta| × 4  × (エリート1.25 / ボス1.5) × (🥇所持なら0.75)
時間切れ = 8 に同じ倍率
報酬 = (8 + 3×累計delta) × エリート2.5+20 / ボス+日別ボーナス
       × イベント倍率(エレベーター2倍) × 本日の回数倍率 × 👔1.25 × 🎤1.15
```

### アイテム(全16種)

**ガジェット(8)**: 👔シャツ(報酬+25%) / 🎧翻訳イヤホン(ゲージ1.25倍) / 💼名刺入れ(30%で最悪の選択肢が消える) / 🎫クーポン(売買20%有利) / 🧿お守り(HP0で1度復活) / 🏆トロフィー(高く売れる) / 🎤座長の推薦状(報酬+15%、Day1ボス) / 🥇大御所の名刺(被ダメ-25%、Day2ボス)

**レリック(3)**: 持ったまま**完走**するとボーナス。📓notebook(⭐+150) / 🛂パスポート(💎+15) / 🎀リボン(⭐+100と💎+10)。お店の高額商品で、売って現金化するか持ち続けるかの駆け引き

**ドリンク(3)**: ☕コーヒー(次の会話のゲージ2倍) / 🧃栄養ドリンク(🧠+15) / 🍀招待状(研究者ノードをスキップ)

**バッド(2)**: 😪時差ボケ(ゲージ0.8倍) / 📚プロシーディングス(30%でdecoy選択肢が混入)。お店で売って処分できる

### ボス

| Day | ボス | ターン | 特徴 |
|---|---|---|---|
| 1 | 👑セッション座長 | 4 | アブストとの食い違い、学生セッションへの誘い |
| 2 | 👑分野の大御所 | 5 | 過去の失敗例との比較、未発表の矛盾データ、科学観への問い |
| 3 | 👑鋭いReviewer | 5 | 因果と相関、オフターゲット、**反証可能性**。制限時間0.75倍 |

### 終了パターン

| 結果 | 持ち帰り |
|---|---|
| 🎓 学会制覇(Day3クリア) | 研究費全額 + 完走ボーナス100pt + 💎5 + レリックボーナス |
| 🏳️ 途中で切り上げ(マップ下部のボタン) | 研究費の**40%** |
| 💤 ゲームオーバー | 研究費の**10%** |

いずれの場合もXP・実績・図鑑は残る。

## 5. 継続システム

`js/progress.js`。Duolingo型の習慣化の仕組み。

| 要素 | 内容 |
|---|---|
| 💎ジェム | 実績解除+10、クエスト+2〜3、全達成+5、学会制覇+5。ホームの💎バッジからジェムショップへ |
| ジェムショップ(5種) | 次のランに適用される特典。🎧/👔持参(各20) / 🧿お守り(30) / 💰+50(15) / 🧠上限+15(25) |
| 📋デイリークエスト(4種) | 朝活(7〜12時) / 夜活(19時〜) / お店で💰50消費 / 学会攻略で会話1回。毎日0時更新、達成で自動付与 |
| 🏅実績(16種) | 連続ログイン(3/7/30日)、初練習、初要約、Sランク、学会制覇、ボス全ベスト、ゲームオーバー、スロット大当たり、全クエスト達成、💎100、レリック2つで制覇、全アイテム発見、撤退 |
| 📖アイテム図鑑 | 全16種のアイコンを表示。未発見は暗く効果非表示、発見済みは明るく効果と初取得日を表示 |
| 週間グラフ | 曜日別の獲得ポイント。今日はオレンジ |
| 連続/累計学習日数 | アプリ起動日ベース |
| 報酬倍率 | 学会攻略は本日1回目1.5倍 / 2回目1.0 / 3回目以降0.7。**回数制限なし** |

### スタミナ制を採用しない理由(重要な設計判断)

学習を止める仕組みは、このアプリの目的(11月・1月に向けた準備)と衝突する。最大の敵は「やらないこと」であり「やりすぎ」ではない。また講演録音は学会当日に使う実用機能のため、残量で使えなくなる事態は避ける。代わりに報酬の逓減で「毎日少しずつ」を誘導する。一般公開時にAI機能(実費がかかる)へクレジット制を導入するのは正当だが、その場合も学習機能自体は止めない。

## 6. 共通の仕組み

### AI連携(`js/ai.js`)

- **文字起こし**: OpenAI(whisper-1 / gpt-4o-transcribe / gpt-4o-mini-transcribe)。**whisper-1のみタイムスタンプ対応**(スライド別集計に必須)
- **テキスト生成**: Claude と OpenAI GPT を設定で切替。同じ練習を両方に評価させて比較できる
- APIキーはlocalStorageに保存(端末内のみ)

### Markdownレンダラー(app.js内 `renderMarkdown`)

外部ライブラリ不使用の自作。見出し・箇条書き・番号付き・太字・コード・引用・水平線・リンク・コードブロック・**表**に対応。HTMLを先にエスケープするためAI出力にタグが含まれても安全。

### UI基盤

- `appAlert()` / `appConfirm()`: ブラウザ標準のalert/confirmは「rafysta.github.ioの内容」というタイトルが出て消せないため、アプリ内モーダルに置換済み。**新規コードでもalert/confirmは使わないこと**
- `showToast()`: 画面下部の一時通知
- エラーバナー: 画面上部に赤く表示。`window.__earlyErrors`で読み込み中のエラーも捕捉

### 更新の仕組み(過去に2度事故った箇所)

- SWは同一オリジンを`cache: 'no-store'`で取得しHTTPキャッシュを迂回
- `sync-version.js`が**index.htmlの全JS/CSS参照に`?v=バージョン`を自動付与**。これにより「古いHTML+新しいJS」の混在が構造的に起こらない
- 起動時に`version.json`を照合し、新版があればホームに通知バナー
- アプリ情報画面に「実行中」と「サーバー最新」を並べて表示 + 完全リセットボタン

## 7. リリース手順

1. `js/version.js` の `APP_VERSION` を上げ、`CHANGELOG` の**先頭**に変更を追加(不一致だとツールがエラーで止まる)
2. `node tools/sync-version.js` を実行
3. `sw.js` の `CACHE_VERSION` を上げる
4. このファイル(implementation-notes.md)を更新
5. commit して push

## 10.5 📅 予定の講演と事前情報 (v1.38.0)

**目的**: 学会の前に講演情報を登録し、会場では「選んで ● 録音を開始」だけで始める。登録した情報を文字起こし・要約・質問づくりの 3 か所で使う。

- **js/plans.js (`Plans`)**: `lq_talk_plans` に JSON 配列。`upcoming()`(未使用、日付順・空欄は最後)/ `done()`(`usedAt` あり)。`markUsed(id, talkId)` は録音・読み込み・テキスト作成のどの経路でも app.js の `markPlanUsed(meta)` から呼ぶ。
- **事前情報は録音にコピーして持つ**: `Talk.current.prep = Plans.snapshot(plan)` = `{planId, abstract, notes, terms[], affil}`。予定を消しても録音側に残る。`Talk.save()`/`load()`/`RecJournal`(途中保存)にも `prep` を含める。
- **Whisper prompt**: `Talk.sttPrompt()` → `Plans.whisperPrompt()`。形は `Talk: <title>. Speaker: <who>. Key terms: a, b, c.`(リストより「書き起こしの冒頭」に見える自然文のほうが効く)。**Whisper は prompt の末尾 224 トークンしか使わない**ので、語彙を末尾に置き、700 文字を超えたら**前から**切る。予定なしの録音でもタイトル・発表者は渡す。ミーティングは渡さない。`STT.transcribe(blob, lang, prompt)` の第3引数(以前から存在、講演では未使用だった)。
- **要約**(`Talk.summarize`): user に「講演前に用意した事前情報」として `Plans.contextText(prep)`(抄録+下調べ、14000 文字上限)。system に「事前情報の用語と音が近い聞き間違いは直してよい / 事前情報にしか無い内容を講演で述べたことにしない / 以前の主張との違いを結論に明記」。
- **質問**(`QGen.generate` に `ctx.prep`): 以前の論文との違い・抄録にあって話されなかった点・未解決の問いへの答え、を高価値の質問として促す。根拠は必ず今回の講演に置く。
- **下調べの入手**: `Plans.requestText(plan)` が Claude(チャット)への依頼文を作る(見出し固定: 研究の流れ / 最近の主要論文 / 予想される内容 / 論点 / 質問の切り口 / **語彙リスト**)。`lq_my_research` があれば添える。貼り戻すと `Plans.termsFromPrep()` が「## 語彙リスト」(Glossary/Terms/用語 も可)の下のカンマ区切り・箇条書きから語彙を拾い、語彙欄が空なら自動で入れる。無ければ 🧠 `Plans.generateTerms()`(AI、effort low)。
- **画面**: `screen-talk-plans`(一覧、行の右に ● 録音)/ `screen-talk-plan-edit`(フォーム)。talk-setup 最上部の `#talk-plan` セレクトは `refreshPlanPicker(selectId)` で作り直し、`applyPlanToForm()` がタイトル等を写す。入口はホームの学会モード欄と talk-setup 内。
- **テスト**: `/tmp/.../v138-test.js`(34項目)。`STT.transcribe`/`AI.chat` を差し替えて **prompt と事前情報が実際に API 呼び出しへ届くか**を検査する。**同じミリ秒に2件保存すると id が衝突する**バグをこのテストで発見した(`Plans.save()` で `while` 加算)。

### 10.5.1 📤📥 予定の端末間受け渡し (v1.40.0)

**目的**: PC で抄録・下調べを貼って作った予定を、会場で使う携帯へ運ぶ。`lq_talk_plans` は端末ごとの localStorage なので、何もしないと PC の予定は携帯に出てこない。💾バックアップの復元は**全部置きかえ**(携帯側の学習の進行まで消える)なので使えない。

- **書き出し**: `Plans.exportPayload(list)` = `{kind:'confquest-talk-plans', format:1, exportedAt, plans:[{id, createdAt, updatedAt, title…terms}]}`。**`usedAt`/`talkId` は運ばない**(相手の端末では未使用の予定)。
  - ファイル: `exportJson()` → `showSaveFilePicker`(PC の Chrome/Edge。Nextcloud の同期フォルダを選べる。**クリック直後しか開けない**ので JSON を作る前に開く…ここでは JSON が同期的に作れるので順序の問題は無い)/ 非対応ならダウンロード。
  - テキスト: `exportText()` = 説明文 + `#### CONFQUEST PLANS BEGIN ####` + UTF-8→Base64(76 文字改行)+ END。**Base64 にするのは、メールアプリの引用符の置きかえ・改行の挿入・引用記号 `>` で JSON が壊れないため**。**目印に `---` を使わない**(Gmail が署名として折りたたむ。v1.24 で経験済み)。コピー / `navigator.share({text})`。
- **読み込み**: `Plans.parseImport(text)` は目印つきテキスト(前後に別の文章があってよい。目印の間は Base64 の文字だけ拾う)/ JSON / 配列そのもの を受け付け、フィールドを `FIELDS` に限定・長さを `FIELD_MAX` で切って正規化する。`format` が新しすぎたら「アプリを更新して」。
- **統合**: `planImport(incoming)` が各予定に action を付ける。**同じ予定 = `id` と `createdAt` が両方一致**(id は `Date.now()` なので別端末の別予定と偶然重なり得る)。`add`(無い)/ `same`(中身が同じ)/ `older`(この端末の `updatedAt` のほうが新しい → 触らない)/ `update`(上書き。**`usedAt`/`talkId` はこの端末のまま**)。`applyImport(items)` が書き込む。新規の id が衝突したら振り直す。`MAX`(60) を超えたら録音済みの古いものから落とす。
- **`updatedAt`**: v1.40.0 から `Plans.save()` が毎回付ける。それ以前の予定には無いので、比べられないときは読み込む側を採る。
- **画面**: 一覧に `#btn-plans-export`(未使用の予定すべて)/ `#btn-plans-import`、編集画面に `#btn-plan-export-one`(保存してから 1 件だけ)。確認ダイアログが長くなるので `.modal-box` に `max-height: 88vh; overflow-y: auto` を足した。`appPrompt()` に第5引数 `opts {ok, cancel, rows}` を追加(既存の呼び出しは変わらない)。

### 10.5.2 📖 下調べを整形して読む (v1.41.0)

- 編集画面の下調べ欄に「📖 読む / ✏️ 貼り付け・編集」の切り替え(`.prep-tabs`)。読むときは `#plan-prep` の中身を **録音の要約と同じ `renderMarkdown()`**(`groupUnderHeadings()` の節・入れ子の箇条書き・表)で `#plan-prep-rendered` に描く。データは textarea 1 つだけで、読む表示は毎回そこから作り直す(二重管理しない)。
- `setPrepMode('read'|'edit')`。`openPlanEdit()` は**下調べがあれば読む**、無ければ編集で開く。
- 録音設定(`talk-setup`)で下調べのある予定を選ぶと `#btn-talk-plan-read` が出て、`openPlanEdit(id, 'talk-setup')` で開く。← で戻っても `refreshPlanPicker()` が選択を保つ。

### 💡 文字起こし・要約の待ち時間にも質問候補を見せる (v1.42.0)

- **v1.41.0 までの問題**: 「終了して要約」で `talkTranscribeStep()` が `#talk-result-content` をスピナーだけに置きかえていたため、録音中に 💡 で作った質問(`Talk.current.questions`, `partial:true`)が要約の完成まで見えなかった(要約側の `#talk-q-first` は文字起こしが終わってから作られていた)。
- **今の形**: 結果画面を `#talk-q-first`(質問の枠)と `#talk-progress`(進み具合)に分ける(`ensureTalkProgressLayout()`)。文字起こし・要約のあいだは `setTalkProgress(text)` で進み具合だけ書きかえ、**質問の枠は作り直さない**(開いた `<details>` と⭐が保たれる)。
- `renderPendingQuestions(note)`: 中身は `Talk.current.questions` の**参照が前回と違うときだけ**描き直す(`box._qs`。`makeQuestions()` は毎回新しいオブジェクトを入れる)。note は注記だけ書きかえる。
- `_earlyQPending`: 💡 の結果を待っている間に「終了して要約」を押した場合、枠にスピナーを出し、返ってきた時点で `renderPendingQuestions()` を呼ぶ(全文版が先にできていれば `makeQuestions()` 側で途中版を捨てる)。`resetEarlyQuestionUI()`(録音開始)で戻す。
- `renderTalkRetry()`(文字起こしがほぼ空)にも質問候補を出す。
