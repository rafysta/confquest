# ConfQuest 言語学習モジュール「Language Quest」設計考察

対象: 韓国語(2026年11月 ISSY39)と広東語(2027年1月 結婚式)。最終目標は「同僚や結婚相手のご両親と簡単な会話ができる」こと。本書は実装前の考察・設計書であり、docs/game-design.md(学会攻略モード)の姉妹編にあたる。

## 1. ゴールを先に運用的に定義する

「簡単な会話ができる」を具体化しないと、教材アプリの一般形(文法・単語の網羅)に流れてしまう。3ヶ月×2言語という条件では網羅は不可能なので、次の3つに絞る。

1. **自分から言える定型フレーズ 20〜30個**(挨拶・感謝・乾杯・自己紹介・褒める・別れ際)
2. **相手の頻出質問を聞き取って、型で返せる**(「日本から?」「お酒は?」「おいしい?」→ 各3秒以内に返答)
3. **聞き取れないときの切り抜けフレーズ**(「もう一度お願いします」「韓国語は少しだけです」)— 実はこれが会話の生命線

重要な洞察: 会話力とは知識ではなく**想起速度**である。「知っている」と「1秒で口から出る」の間に大きな壁があり、この壁を越えさせるのが本モジュールの仕事。制限時間付きで最適な発言を選ぶというConfQuestの既存メカニクス(選択肢バトル)は、まさに想起速度の訓練であり、語学と本質的に相性が良い。

### 言語ごとのゴール像

| | 韓国語(11月) | 広東語(1月) |
|---|---|---|
| 相手 | 学会ホスト・元同僚・学生 | パートナーのご両親 |
| 場面 | 懇親会、食事、車中2時間、シンポ | 顔合わせ、飲茶・食事、式当日 |
| 支援者 | なし(ぶっつけ本番) | **パートナー(ネイティブ)が隣にいる** |
| 目標枚数 | コア30 + 周辺40 ≈ 70フレーズ | コア25 + 周辺25 ≈ 50フレーズ |
| 特記 | 英語に切り替えられる保険がある | 発音(声調)が通じやすさに直結 |

広東語は「パートナーが助けてくれる」前提を設計に組み込めるのが最大の特徴(後述のパートナー録音・ヘルプ機能)。

## 2. 継続の仕組み — 何が続き、何が続かないか

英樹さんはDuolingo連続350日の実績があり、「ストリーク+デイリークエスト+小さなセッション」が本人に有効なことは実証済み。したがって新しい習慣システムを発明するのではなく、**v1.0.0で実装済みの継続システム(Login連続日数・デイリークエスト・Gems・実績・週間グラフ)にそのまま乗せる**のが正解。学習の入口を増やすのではなく、既にある毎日の動線(クエスト画面)に「今日の復習 12枚」が現れるようにする。

継続設計の原則を3つ置く。

1. **1セッション3〜5分で完結**。復習12枚+新規3枚が1セッションの標準。通勤・待ち時間で回せる粒度。
2. **「新しいものを増やす」より「持っているものが育つ」**。戦略SLG好きの英樹さんには、毎日レベルが上がる・進化するという育成の手応えが効く(Duolingoに欠けている部分でもある)。
3. **本番の日付との接続**。ホーム画面に「ISSY39まであと n 日」「結婚式まであと n 日」のカウントダウンを常設し、進捗(習得済み/目標枚数)を並べる。締切が実在するのはこのアプリ最大の強みで、汎用語学アプリには真似できないモチベーション源。

さらに感情面の接続として、覚える相手が実在する点を活かす。ゲーム内の会話相手を「Prof. Kim(ホスト)」「お義父さん・お義母さん」のようなキャラクターにし、フレーズを覚えるほど好感度ゲージが育つ。ゲージの先に本物の懇親会と結婚式がある、という構図そのものが物語になる。

## 3. コア設計: フレーズカード育成 × 間隔反復(SRS)

### 3.1 フレーズ=育てるカード

1フレーズ=1枚のカードとして扱う。カードには韓国語(ハングル+カタカナ+ローマ字)/広東語(漢字+カタカナ+イェール式)、日本語、使用場面、音声、ミニ解説(minigames.jsのnote方式)を持たせる。

カードは使い込む(=正しく想起する)ことで成長する。成長段階を想起の深さと一致させるのが本設計の核:

| カードLv | 段階 | 出題形式 |
|---|---|---|
| Lv1 🌱 | 認識できる | 4択(韓国語→意味、意味→韓国語)。既存LANG_QUIZ形式 |
| Lv2 🌿 | 聞き取れる | 音声を聞いて意味/表記を選ぶ |
| Lv3 🌸 | 思い出せる | 日本語だけを見て、シャッフルされた選択肢や語順並べ替えで再構成。制限時間つき |
| Lv4 ⭐ | 言える | 録音して発音判定(Whisper)。合格でマスター(金枠) |

「コレクションを金枠で埋めたい」という収集欲と、「Lv4カードだけが本番で使える力」という実利が一致する。カード一覧画面はデッキ図鑑として眺められるようにし、シナリオ単位の束(「乾杯セット」「ご両親ご挨拶セット」)をコンプすると称号+💎が出る。

### 3.2 SRS(簡易SM-2)

各カードにbox(0〜5)と次回復習日を持たせ、正解でbox+1、不正解でbox-2(下限0)。復習間隔は 当日/1日/3日/7日/14日/30日。状態はlocalStorage(`lq_srs`)、実装は50行程度で足りるので外部ライブラリ不要。

毎日の復習キューはデイリークエストに自動接続する(「📖 今日の復習を終える」を既存4種に追加)。復習が溜まりすぎると挫折の最大要因になるため、**1日の復習上限を20枚にキャップ**し、超過分は翌日に繰り越す(Ankiで挫折する典型パターンの回避)。新規カードの導入も1日3〜5枚に制限し、「今日は少ししかできなかった」日でも失敗感が出ないようにする。

### 3.3 既存システムとの共有

ローグライク(学会攻略モード)のお宝ノードにあるLANG_QUIZは、このSRSデータと双方向に接続する。ラン中に語学クイズへ正解するとSRSにも正解が記録され、逆に出題はSRSの「そろそろ復習」カードから優先的に引く。**遊んでいるだけで復習が進む**構造にすると、学習モードを開かない日もカードが劣化しない。

## 4. ゲームモード設計

### 4.1 Language Quest マップ(路線図型)

ローグライク(ランダムマップ・周回型)とは別に、**固定の路線図を進むステージマップ**を用意する。Duolingoのパス構造に、ConfQuestの世界観と旅程を重ねたもの。

- **Korea Route**: 空港到着 → ホテルチェックイン → 学会会場 → 懇親会 → 【車中2時間】 → シンポジウム → 打ち上げ → 帰国
- **Hong Kong Route(Wedding Quest)**: 初対面のご挨拶 → 飲茶 → 家族の食卓 → 街歩き → 式前日 → 【結婚式当日】

各駅 = そのシーンのフレーズ束(新規カード導入)+ ミニゲーム数問 + 小ボス(そのシーンの会話バトル)。駅をクリアすると次の駅が開き、実際の旅程を先取りして歩く構図になる。ステージが現実の時系列と同じ順番なので、「いまゲームで空港にいる自分」が11月に本当に空港に立つ、という予行演習の実感が出る。

### 4.2 会話バトルとの統合 — 学習と実戦のループ

v0.6.0の選択肢バトル(好感度ゲージ)をそのまま多言語対応する。設計上のポイントは、**習得済みカードだけが正解選択肢として登場する**こと。学習パートで覚えたフレーズが数日後にバトルで「使える手札」として出てくると、学んだものが武器になる感覚が生まれる(未習得フレーズが正解に混ざると理不尽感になるので厳禁)。

言語の混合は段階的に行う:

1. 場面説明・相手のセリフは日本語、選択肢だけ韓国語(序盤)
2. 相手のセリフが韓国語音声+日本語字幕(中盤)
3. 字幕なし、聞き取ってから選ぶ(終盤・ボス)

### 4.3 ボス戦「質問攻め」

シーンの締めは既存の複数ターン会話バトル形式のボスで、TTSが質問を読み上げ → 意味を選ぶ(聞き取り)→ 返答フレーズを選ぶ(想起)→ 上級では録音して言う(発話)、の3段階を1ターンに圧縮する。Wedding Questのラスボスは「ご両親との食事会」(お義父さん・お義母さんの2連戦)で、**パートナーヘルプ**を1戦闘3回まで使える(ヒント表示・時間延長)。ゲーム内の救済措置と、本番で実際に隣にいてくれるパートナーが一致しているのが世界観として美しい。

### 4.4 ミニゲームの追加候補(お宝ノード・駅の彩り)

- **声調スロット(広東語)**: 同じ音節の声調違いを聞き分ける2択の連打
- **聞き取りキーワードハント**: 短い音声から知っている単語を拾ってタップ
- **速答モード**: 10問連続、正解ごとに制限時間が短くなるサドンデス(想起速度の直接訓練、ハイスコアはランキング実績に)

## 5. 「聞く・話す」の技術設計

### 5.1 TTS(聞き取り)

Web Speech APIの`speechSynthesis`を使う(録音と競合するのは音声認識side=SpeechRecognitionであり、読み上げは問題ない)。

- **韓国語(ko-KR)**: AndroidのGoogle TTSで標準的に利用可能。通常速度に加え0.7倍のスロー再生ボタンを付ける。
- **広東語(yue-HK / zh-HK)**: **Android端末に音声が存在しないことが多い**(Googleのフォーラムでも報告あり)。あることを前提にしてはいけない。

対策として、設定画面に**音声チェッカー**(利用可能なvoice一覧を診断し、韓国語・広東語それぞれ「この端末で再生可能か」を表示)を用意し、広東語が不在の端末では次のパートナー録音に誘導する。

### 5.2 パートナー録音 — 広東語の切り札

パートナーが広東語ネイティブであることを技術的な弱点(TTS不在)の解決策にする。フレーズカードごとに**パートナーのお手本音声を録音して紐付ける**機能(既存MediaRecorderの流用で実装は軽い)。

これはフォールバックを超えた価値がある: 合成音声より正確な発音・自然な速度で学べる、ご家庭で実際に使う言い回しに直せる(教科書広東語との乖離をネイティブが修正できる)、そして**二人でアプリに吹き込む作業自体が結婚準備の思い出になる**。録音データは容量の観点からlocalStorageではなくIndexedDBに保存する(数十フレーズ×数秒なら十分収まる)。韓国語も、11月に会う元同僚に数フレーズ吹き込んでもらえたら同じ仕組みに載る。

### 5.3 発音チェック(Whisper)

既存の録音+Whisper API(発表練習で実装済み)を発音判定に転用する。

- **韓国語**: `language=ko`で精度は高い。認識結果と目標フレーズをハングル正規化後に編集距離で比較。
- **広東語**: Whisperに`yue`指定は挙動が不安定という報告があり、**`language=zh`(中国語)を指定して繁体字の認識結果と照合**するのが現実的。精度は韓国語より落ちる前提で扱う。

判定は⭐〜⭐⭐⭐の3段階とし、**意図的に甘くする**(類似度60%で⭐、80%で⭐⭐⭐など、実測で調整)。目的は「通じる発音」であり、厳しい判定は学習意欲を折るだけ。⭐1つでもLv4合格とし、⭐⭐⭐は追加💎で称える。判定前に必ずお手本(TTSまたはパートナー録音)を聞き直せるUIにする。

## 6. 車中2時間モードとAI自由会話(将来拡張)

**ドライブモード(聞き流し)**: 画面注視不要の連続再生モード。「日本語 → ポーズ(自分で言ってみる) → 韓国語お手本」の順で復習カードを流し続ける。移動中・家事中に画面を見ずに回せる復習手段として価値が高く、TTSの連続再生だけなので実装も軽い。なお「車中2時間の雑談」自体の対策は、語学モジュールよりも英語の話題ストック(既存の会話トレーニング側)の領分なので、そちらに「ロングドライブ」シナリオを足すのが筋が良い。

**AI自由会話**: 習得済みフレーズをパレット表示した状態でのAI相手のロールプレイ(相手役は韓国語で話し、詰まったら日本語でコーチしてくれるハイブリッド)。既存ai.jsで実装可能だが、優先度は低い。選択肢式のほうがAPI消費が少なく、確実に回り、暗記の土台ができてからでないと自由会話は「何も言えない体験」になって逆効果のため、Phase 3以降とする。

## 7. コンテンツ計画と逆算スケジュール

### ユニット構成(案)

韓国語 8ユニット: ①基本の挨拶・返事 ②自己紹介 ③感謝と謝罪 ④食事 ⑤乾杯・お酒の席(韓国の作法込み) ⑥研究の話の入口 ⑦切り抜けフレーズ ⑧別れ際・再会の約束

広東語 6ユニット: ①ご挨拶・自己紹介 ②感謝(多謝/唔該の使い分け) ③食事・飲茶 ④家族の話題・褒める ⑤式当日のフレーズ ⑥切り抜けフレーズ

フレーズ原案はAIで下書き生成し、**広東語はパートナー監修を必須**とする(データはscenarios.js方式でjs/phrases.jsに分離、監修しやすい形にする)。

## 8. 実装フェーズ

1. **Phase 1(コア学習ループ)**: フレーズカード+簡易SRS、Lv1〜Lv3の出題(4択・聞き取り・並べ替え)、TTS+音声チェッカー、デイリークエスト接続、カード図鑑、カウントダウン表示
2. **Phase 2(話す+マップ)**: Whisper発音チェック(Lv4)、パートナー録音、Korea Route路線図マップ、小ボス会話バトル(習得カード連動)、ローグライクのLANG_QUIZとSRS共有
3. **Phase 3(Wedding Quest+拡張)**: Hong Kong Route、ご両親ボス戦+パートナーヘルプ、ドライブモード、声調スロット等の追加ミニゲーム、AI自由会話(様子を見て)

従来どおり各Phaseを動く状態でリリースし、実際に毎日使った感触で調整する。特にPhase 1は8月中に出し、「11月まで毎日回す」期間を最大化することが何より重要。

## 9. リスクと対処

- **広東語TTSが端末にない**: 前提として設計済み(音声チェッカー+パートナー録音)。カタカナ+イェール式表記は常に併記。
- **Whisperの広東語精度**: 判定を甘めに設計し、`language=zh`+繁体字照合。実機テストで閾値を決める。ダメなら広東語のLv4は「パートナー録音と聞き比べて自己判定」に切り替える逃げ道を残す。
- **復習負債による挫折**: 復習上限20枚/日+新規導入の制限で構造的に防止。
- **コンテンツの質**: AI生成はあくまで下書き。広東語はパートナー、韓国語は可能なら元同僚のチェックを通す。
- **開発時間**: Phase 1のスコープを絞る(マップもボスもPhase 2)。学習ループが8月中に回り始めることを最優先。
