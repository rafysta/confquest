# 🎓 キャリア称号システム 設計書

対象バージョン: v1.13.0で実装 / 作成日: 2026-08-16 / ステータス: **実装済み**

> **⚠️ v1.14.1追記(実測によるバランス調整)**: 実運用2日で4,183pt(准教授)に到達し、§5の試算(60〜100pt/日)が大幅に外れた(ミニゲーム・ラン完走・初回コンテンツの寄与が想定超)。そこで§3のラダーを次のとおり改訂した: 准教授まで(0〜3,200)は**据え置き**、👑教授9,000 → 🏫学部長16,000 → 🌟名誉教授25,000 → 🏆学会長36,000 → 🎖️学界の重鎮50,000 → 🌏世界的権威68,000 → 🪐伝説の研究者90,000の**全14段階**。あわせて`CareerRank.effectiveIndex()`を導入し、**一度到達した称号はしきい値をどう調整しても失わない**(表示=max(pt導出, claimedIdx))。以降の調整もこのルールの下で`need`を自由に動かせる。

## 1. 目的と現状分析

⭐ptは現在、全モジュールの獲得ポイントが `Gami.addPoints()` に合流する**累計スコア**だが、出口が「ホームのバッジ表示」と「週間グラフ」の2つの表示しかなく、貯める意味が薄い。

一方で⭐ptには他の通貨にない性質がある:

| 通貨 | 性質 | 役割 |
|---|---|---|
| ⭐pt | **減らない・全活動が合流** | 生涯業績(現状は表示のみ) |
| 💎ジェム | 消費する | ランを有利に始める特典の購入 |
| 💰研究費 | ラン内限定 | お店での売買、終了時に⭐へ換金 |

この「減らない・全活動の合計」という性質は、**生涯業績にもとづくキャリア進行**と相性が良い。ptを消費させる(両替所・ショップ)案は💎の役割と衝突するため採用せず、ptは今後も**貯まる一方**のまま、累計値そのものに意味を与える。

## 2. コンセプト

> ⭐ptは研究者としての「生涯業績」。積み上げると、学部生から始まるキャリアの階段を昇っていく。

アプリのコンセプト「学会をクエストとして攻略」に合わせ、称号は日本のアカデミアのキャリアラダーをなぞる。発表練習も語学学習も学会攻略も、すべてが「研究者としての成長」に集約される。

## 4. 昇格報酬

- 昇格時に一度だけ `gems` の💎を付与(合計💎115。実績1個=💎10と比べても過剰でない)
- 付与済み管理は `lq_career = { claimedIdx: n }`(受け取り済みの最高ランクindex)のみ。配列やマップは不要
- **遡及付与**: 導入時、既存ユーザーは既にptを持っている。初回起動時に現在ptで到達済みの全ランクの報酬をまとめて付与し、「あなたは既に○○です!」というお祝いモーダルを出す(不利益ゼロ・サプライズのあるアップデート体験になる)
- **複数ランク同時昇格**: 学会攻略クリア(+300〜600pt)で2ランク飛ぶことがある。スキップした分の報酬もすべて付与し、演出は最終到達ランクのものを表示

## 5. 到達ペース試算

1日あたりの獲得目安(コードから算出):

| 活動 | pt/回 |
|---|---|
| 発表練習・会話トレ | 10〜40(streakボーナス込み) |
| デイリークエスト全達成 | 65 |
| Language Quest 1セッション | 10〜25 |
| Route駅クリア | 初回30 / 再挑戦10 |
| 学会攻略 完走 | 300〜600(不定期) |

普通に毎日使うと**約60〜100pt/日**、週末に学会攻略を完走すると+400前後。

| 使い方 | 月間pt | 教授(4500)到達 |
|---|---|---|
| 軽め(クエスト+LQのみ) | 約1,500 | 3ヶ月 |
| 標準(+会話トレ・週1ラン) | 約2,500 | 約2ヶ月 |
| 熱心(+発表練習期) | 約4,000 | 1ヶ月強 |

**11月のISSY39までに助教〜准教授、1月の結婚式までに教授**が標準ペースの目安になり、実イベントとゲーム内キャリアが自然に重なる。学会長(10000)は半年スパンの長期目標。

※既存ptの残高によっては導入時点でいきなり中位ランクの可能性がある。その場合も上表の「残りの道のり」が同じ感覚で機能する。

## 6. UI設計

### 6-1. ホーム画面
- streakバナーの `⭐ ○○ pt` バッジに現在の称号アイコンを添える: `🎓 1,234 pt`
- バッジをタップ可能にし、タップでステータス画面のキャリアカードへ(現状ptバッジはタップ不可なので導線を新設)

### 6-2. ステータス画面(メイン)
最上部(4つの数字ボックスの上)に**キャリアカード**を追加:

```
┌─────────────────────────────┐
│ 🎓 ポスドク                    │
│ ⭐ 1,234 pt                   │
│ ▓▓▓▓▓▓▓░░░ 助教まで あと166pt │
└─────────────────────────────┘
```

- カード内タップで**キャリア年表**を展開: 全10ランクを縦に並べ、到達済みは日付入り・未到達はグレー+必要pt表示(実績画面と同じ見せ方)
- 進捗バーは `(points - 現ランクneed) / (次ランクneed - 現ランクneed)`

### 6-3. 昇格演出
- `Gami.addPoints()` の後に昇格判定 → 昇格していたらお祝いモーダル(クエスト受け取りの `playClaimEffect` 系の演出を流用)
- 文言例: 「🎉 昇格! あなたは 🧑‍🏫助教 になりました ⭐1,400pt達成 / 💎+10」
- 戦闘結果画面などの途中では**toastのみ**にして流れを止めない、という代替案もある。実装時にどちらか選ぶ(推奨: リザルト系画面ではモーダル、それ以外はtoast+次回ホーム表示時にモーダル)

## 7. データ設計と実装方針

- **新規storage**: `lq_career = { claimedIdx: number }` のみ。称号自体は毎回ptから導出(Single Source of Truth = `lq_gami.points`)
- **新規モジュール**: `CareerRank`(progress.jsに追加、約80行)
  - `current()` / `next()` / `progress()`: ptから導出
  - `checkUp()`: claimedIdxと比較して未付与ランクの💎付与+演出トリガー。**付与は必ずGems.add()経由**
- **フック**: `Gami.addPoints()` の末尾に `CareerRank.checkUp()` を1行追加(加算がここに一本化されている設計がそのまま活きる)
- **表示**: `renderHome()`(バッジに称号)と `renderStatus()`(キャリアカード)を修正
- **実績との住み分け**: 実績=「特定の行為を一度やった」記録、キャリア=「総量」の記録。重複しない。既存実績への変更なし
- 新規JSファイルは作らないため、index.html / sw.js のファイルリスト変更は不要
- 実装規模の見込み: JS約120行+CSS約40行+テスト。1セッションで実装可能

## 8. エッジケース

| ケース | 挙動 |
|---|---|
| 導入時に既にpt多数 | 到達済み全ランクの💎を一括付与+お祝いモーダル(§4) |
| 1回の加算で複数ランク昇格 | 全報酬付与、演出は最終ランクのみ |
| pt=0の新規ユーザー | 🎒学部生からスタート(報酬なし、違和感なし) |
| localStorage消去 | ptと一緒に称号も初期化される(導出値なので不整合が起きない) |
| 学会長(最高位)到達後 | 進捗バーは「MAX」表示。それ以降のptは週間グラフと数字の伸びのみ(将来の拡張余地: プレステージ/周回称号) |

## 9. バランス調整のつまみ

実機で運用して調整する場合、触るのは以下だけ:

1. `CAREER_RANKS` の `need`(間隔が広すぎる/狭すぎると感じたら)
2. `gems`(💎経済への影響を変えたいとき)
3. 昇格演出の頻度(モーダルがうるさければtoastに)

しきい値変更は導出値なので**いつでも安全に変更できる**(ただし下方修正で「未付与なのに到達済み」が生まれた場合は次回checkUpで自動的に付与される)。
