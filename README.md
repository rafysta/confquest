# ConfQuest

**Level up your conference skills.**

学会を一つのクエストとして攻略する、研究者向けトレーニングPWA(Webアプリ)。発表練習・質疑応答・懇親会会話をゲーム感覚で鍛えます。AndroidのChromeで開き、ホーム画面に追加するとアプリとして使えます。

## 現在の機能(発表練習モジュール)

- **スライド練習**: PDFを読み込み、タップでスライド送りしながら発表練習
- **時間管理**: 全体タイマー、スライドごとの滞在時間、リアルタイム終了予測、ペース警告
- **録音**: 練習を録音し、終了後に聞き直し
- **文字起こし**: 録音をWhisper APIで文字起こしし、WPM(話速)とfiller語(um, uh, so...)をスライドごとに自動集計
- **AIフィードバック**: 改善点3つ・言い回しの改善例をMarkdown整形で表示(Claude / OpenAI GPT を設定画面で切替可能。同じ練習を両方に評価させて比較できます)
- **AI質疑応答シミュレータ**: 質問者タイプ(学生〜厳しい査読者)を選び、発表内容に基づく英語Q&A練習
- **ゲーミフィケーション**: スコア・ポイント・連続日数(ストリーク)

## 学会攻略モード(ローグライク、Phase 1)

学会1日を分岐マップで進むゲーム。設計は `docs/game-design.md` 参照。

- 🧠メンタル(HP)・💰研究費・🎒アイテムを管理しながらノードを選んで進む
- 💬研究者ノード: 短い会話バトル(専用カード20枚)。悪い選択でダメージ、良い会話で研究費
- 🛒お店 / ☕休憩所 / 🎁お宝 / ⭐エリート(マップ最奥、既存シナリオの高難度会話)
- アイテム6種(獲得研究費増、ゲージ低速化、選択肢削除、売買割引、復活など)
- ゲームオーバーでも獲得XPと研究費の10%は残る。進行は自動保存され中断・再開可能
- マップ下部の「🏳️ このランを切り上げる」でいつでもリタイア可能(研究費の40%を持ち帰り)
- クリアで研究費が全額ポイントに換金

Phase 2(実装済み):

- 🎁お宝はミニゲームに: スロット / 学会豆知識クイズ / 韓国語・広東語クイズ(11月の学会・1月の結婚式に直結する基礎フレーズ)
- ❓ランダムイベント: エレベーターで大御所と2人きり(報酬2倍の1ターン勝負)、コーヒーをこぼす、落とし物(たまにバッドアイテム)、抽選会、旧友と再会
- ドリンク3種(使い切り): ☕コーヒー(次の会話のゲージ半減)、🧃栄養ドリンク(回復)、🍀招待状(会話スキップ)。HUDのアイコンをタップして使用
- バッドアイテム: 😪時差ボケ(ゲージ25%高速化)、📚分厚いプロシーディングス(紛らわしい選択肢が混入)。お店で売って処分できる

Phase 3(実装済み):

- **3日構成**: Day 1レセプション → Day 2本会議 → Day 3シンポジウム。日をまたぐと🧠15回復、研究費とアイテムは持ち越し
- **ボス3体**: 👑セッション座長(4ターン) → 👑分野の大御所(5ターン) → 👑鋭いReviewer(5ターン・制限時間25%減)。ダメージ1.5倍
- **特別アイテム**: 🎤座長の推薦状(報酬+15%)、🥇大御所の名刺(被ダメージ-25%)
- **✨レリック**: 持ったまま完走すると特別ボーナス。📓research notebook(⭐+150)、🛂パスポート(💎+15)、🎀Invited Speakerリボン(⭐+100と💎+10)。お店にたまに並ぶ高額商品で、売って現金化するか完走を狙って持ち続けるかの駆け引きになる
- **学会制覇**: 3日間完走で研究費全額+完走ボーナス100ptを獲得
- ⭐エリート(旧最終戦)はマップ中盤に最大1つ出現し、🏆トロフィーを落とす

ボスの会話は `js/bosses.js` で管理しています。

## 継続の仕組み(v1.0.0)

- **💎ジェム**: 実績解除(+10)、デイリークエスト、学会制覇(+5)で貯まる長期通貨。ホームの💎バッジからジェムショップを開き、次のランを有利に始める特典を購入できます(アイテム持参・研究費+50・🧠上限+15)
- **報酬倍率**: 学会攻略は本日1回目が1.5倍、2回目が等倍、3回目以降0.7倍。**回数制限は設けていません** — スタミナ制のように学習を止めるのではなく、毎日やる方が得になる形で継続を促す設計です(この方針の議論は下記「設計方針」参照)
- **📋デイリークエスト**: 毎日0時更新。朝活(7〜12時にログイン)、夜活(19時以降)、お店で💰50消費、学会攻略1回。達成すると⭐と💎が自動付与
- **🏅実績**: 15種。連続ログイン、学会制覇、ボス戦全ベスト、ゲームオーバー(それも経験)など
- **📖アイテム図鑑**: 全アイテムのアイコンが並び、一度でも入手したものだけ明るく表示され効果と初取得日が見られます。未発見のものは効果が伏せられています
- **ステータス画面**: 今週の獲得ポイントの曜日別グラフ、連続学習日数、累計学習日数

データはすべて`js/progress.js`で管理。ポイント獲得は`Gami.addPoints()`を必ず通すこと(週間グラフの記録のため)。アイテム入手は`Run.gainItem()`を通すこと(図鑑の記録のため)。

### 設計方針: スタミナ制を採用しない理由

このアプリの目的は学会・結婚式に向けた準備であり、最大の敵は「やらないこと」です。スタミナ制は「やりすぎ」を止める仕組みですが、それは解決すべき問題ではありません。やる気のある日に練習が止められる体験は、継続の動機をむしろ削ります。また講演録音は学会当日に使う実用機能のため、残量で使えなくなる事態は避ける必要があります。

代わりに、報酬の逓減(1.5倍→1.0倍→0.7倍)で「毎日少しずつ」を誘導し、ジェムには消費先を用意しました。禁止ではなく誘導する設計です。

将来一般公開する場合、AI機能(Whisper・Claude API)には実費がかかるため、**AI機能に限ったクレジット制**は正当です。その場合も学習機能自体は止めない方針とします。

## Language Quest(言語学習モジュール、Phase 1)

韓国語(2026年11月 ISSY39向け)と広東語(2027年1月 結婚式向け)のフレーズを、カード育成×間隔反復(SRS)で覚えるモジュール。設計と考察は `docs/language-learning-design.md` 参照。

- **フレーズ=育てるカード**: 韓国語54枚(8ユニット)・広東語39枚(6ユニット)。🌱認識(4択) → 🌿聞き取り(読み上げ→意味) → 🌸想起(日本語→現地語、制限時間つき)の3段階で成長。⭐発話(録音+Whisper判定)はPhase 2で追加予定
- **間隔反復(簡易SM-2)**: 正解するほど復習間隔が延びる(翌日→3日→7日→14日→30日)。復習は1日20枚まで・新規は**言語ごとに**1日5枚までにキャップし、復習負債による挫折を構造的に防ぐ(韓国語5枚+広東語5枚を同じ日に学べる)
- **✍️監修モード**: 全フレーズを学習状況に関係なく一覧表示し、ネイティブがタップで✅OK/⚠️要修正を付けられる。パートナー(広東語ネイティブ)にこの画面を見せてチェックしてもらい、⚠️のフレーズを後でまとめて修正する運用
- **読み上げ**: Web Speech APIのspeechSynthesis(🔊通常 / 🐢ゆっくり)。設定画面の「音声チェック」で端末の対応を診断。広東語音声が無い端末では聞き取り問題は文字出題にフォールバック
- **📔フレーズ図鑑**: カードのコレクション表示。タップで詳細+読み上げ
- **カウントダウン**: 設定でISSY39と結婚式の日付を入れると、ホームと学習画面に「あと◯日」が表示される
- **既存システムとの接続**: デイリークエスト「📖ことばの習慣」、実績3種(🌱ことばの種 / 🌸花ひらく語彙 / 📗ユニット制覇)、ポイントはGami.addPoints()に合流

データは `js/phrases.js`(フレーズ)と `js/learn.js`(SRSエンジン+UI)。フレーズの追加・修正は `js/phrases.js` を編集してください。**広東語はパートナー監修前のドラフトです。**

## 会話トレーニングモジュール

懇親会・レセプションでの立ち回りを、制限時間つきの選択肢バトルで鍛えます。

- **4場面・全16ターン**: 初対面に話しかける / 沈黙の立て直し / 自分の研究をいつ出すか / 研究以外の雑談
- **好感度ゲージ**: 選択によって相手の好感度が変動。最終的にS〜Dでランク判定
- **制限時間**: 10〜14秒。良い選択を素早くできると即答ボーナス。会話は間の取り方も実力のうち
- **全選択肢に解説**: なぜ良いか/悪いかが日本語で表示され、外した場面は終了後に見直せます
- **ステータス育成**: Networking / English / Confidence / Topics がXPで成長

シナリオは `js/scenarios.js` で管理しています。追加や修正はこのファイルを編集してください。

## 講演の録音・要約モジュール

学会で聴いた発表を記録し、PCで整理できる形にします。

- **録音**: 講演タイトル・発表者を入れて録音開始(個別講演単位、30分程度まで)
- **「ここは重要」ボタン**: 押した時刻の前後が、要約で重点的に扱われます
- **AI要約**: 概要 / 背景と問い / 手法 / 主要な結果 / 結論 / 質問候補 / キーワード の構成で自動生成
- **共有**: Androidの共有シートからNextcloud・Gmailなどに送信(Nextcloudを選べばPCの同期フォルダに自動で届きます)。ファイル保存とクリップボードコピーにも対応
- **聴講した講演**: 保存した要約を後から見返して再送信できます

## 使い方

### スマホ(Android)で使う

1. このフォルダをWebサーバーで公開する(下記「公開方法」参照)
2. AndroidのChromeでURLを開く
3. メニュー → **「ホーム画面に追加」** でアプリ化
4. 設定画面でAnthropic APIキーを入力(AI機能を使う場合)

### PCで試す

```bash
cd confquest
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

※ `index.html` をダブルクリックで直接開くと音声認識・Service Workerが動きません。必ずサーバー経由 (http/https) で開いてください。

## 公開方法(GitHub Pages 推奨・無料)

1. GitHubで新しいリポジトリ `confquest` を作成: https://github.com/new
2. このフォルダから push:

```bash
cd confquest
git remote add origin https://github.com/rafysta/confquest.git
git push -u origin main
```

3. GitHubのリポジトリページ → Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `(root)` にして保存
4. 数分後 `https://rafysta.github.io/confquest/` で公開されます(httpsなので音声認識・マイクも動作)

**注意**: リポジトリをPublicにするとコードは誰でも見られますが、APIキーはコードに含まれず各端末のブラウザ内にのみ保存されるので安全です。

## APIキーの取得

いずれも設定画面に貼り付けます(この端末のブラウザにのみ保存されます)。

- **OpenAI APIキー**(必須。文字起こし用。約0.45〜0.9円/分): https://platform.openai.com → API Keys → Create new secret key
- **Anthropic APIキー**(任意。AIフィードバック・質疑応答をClaudeで行う場合): https://console.anthropic.com → API Keys → Create Key

AIフィードバックのプロバイダは設定画面で切り替えられます。両方のキーを入れておけば、同じ練習をClaudeとGPTの両方に評価させて質を比べられます(フィードバック欄の先頭に使用モデルが表示されます)。

## 技術構成

- 純粋なHTML/CSS/JavaScript(ビルド不要)
- PDF表示: [PDF.js](https://mozilla.github.io/pdf.js/) (CDN)
- 録音: MediaRecorder API
- 文字起こし: OpenAI Whisper API(録音終了後にまとめて処理。リアルタイム認識はAndroidで録音と競合し通知音も鳴るため不採用)
- AI: Anthropic Claude API(ブラウザから直接呼び出し)
- オフライン対応: Service Worker(AI機能以外はオフラインで動作)

## バージョン管理とリリース手順

アプリ内の「アプリ情報」画面で、**この端末で実行中**のバージョンと**サーバー上の最新**バージョンを並べて確認できます。起動時にも自動で確認し、新しいバージョンがあればホーム画面に通知が出ます。

更新されない場合は、この2つの数字を見比べてください。

- サーバー側が古い → GitHubへのpushかGitHub Pagesの反映がまだです(反映に数分かかることがあります)
- サーバー側が新しいのに実行中が古い → 「完全リセットして再取得」を押してください

### リリース手順

1. `js/version.js` の `APP_VERSION` を上げ、`CHANGELOG` の先頭に今回の変更を追加
2. `node tools/sync-version.js` を実行(`version.json` への同期と、`index.html` の全JS/CSS参照への `?v=バージョン` 付与を行います)
3. `sw.js` の `CACHE_VERSION` を上げる
4. commit して push

`version.json` はサーバー側の更新検出に、`?v=` はデプロイ直後の新旧ファイル混在の防止に使われるため、**手順2を飛ばすと更新まわりの不具合が起こります**。
